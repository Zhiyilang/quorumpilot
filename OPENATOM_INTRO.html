一、项目背景：智能体最大的风险不是答错，而是「它说了就算」

2026 年，把大模型接进业务流程已成常态。但一个被广泛低估的问题是：智能体的措辞会直接影响结论。 同一个事实，换个说法、换个顺序、多一句铺垫，模型给出的判断就可能翻转。这意味着结论无法审计、无法复现、无法追责。

更现实的问题是：单一智能体既当「证据收集者」又当「裁判」，它既可能漏看关键证据，也可能为了自圆其说而编造证据。

QuorumPilot 的回答是权力分离：智能体只能提议， 验证器决定什么算证据，仲裁器决定怎么做——而仲裁器不使用任何模型。

二、技术架构：三层，越往下越不能商量

层职责关键性质
专家智能体
agents.py		 4 位不同立场的专家就同一提案分别给出主张（claims），每条主张必须自带证据 可替换、可增删；允许犯错
验证器
verify.py		 verify_claims() 逐条核对主张与证据；对不上证据的主张直接丢弃，不进入裁决 确定性、纯代码、无模型
仲裁器
arbitrate.py		 arbitrate() 基于通过验证的证据集产出裁决与理由，结论逐条可回溯到证据 不使用模型——不受措辞影响

配套 receipts.py 把每一次裁决写成只追加凭据（谁主张了什么、证据是什么、哪些被丢弃、最终怎么判）， 事后可完整回放。项目同时提供 MCP 服务器，可被任意外部智能体宿主直接调用。

三、应用场景

任何「结论必须有据可查、且事后要能复盘」的高风险决策场景，都可以直接套用这套权力分离结构：

  • 金融与交易风控：多位专家对同一笔交易分别给出风险主张，验证器剔除无证据主张，仲裁器产出可执行裁决（放行 / 谨慎放行 / 拒绝）。演示视频中三种裁决均有真实运行输出。
  • 合规与合同审查：把「合同条款是否满足某条监管要求」变成可举证的逐条主张，避免模型一句"符合要求"就定案。
  • 运维变更评审：变更提案先过专家意见与证据核验，再由确定性规则决定是否允许上线。
  • 内容审核与事实核查：多视角主张 + 证据核验 + 可回溯裁决，天然适合需要申诉复核的场景。

四、创新点

  • 裁决不受措辞影响。仲裁器不使用模型，只消费已通过验证的结构化证据集。同一组证据无论专家怎么措辞，裁决结果一致——这消除了"换个说法结论就翻转"这一根本风险。
  • 证据先于结论。主张必须自带证据，验证器会主动丢弃对不上的主张；被丢弃了什么、为什么，全部记录在凭据里，而不是悄悄忽略。
  • 可审计而非需被信任。只追加凭据链让每一次裁决都能完整回放：谁说了什么、哪条证据被采信、哪条被丢、最后怎么判。
  • 零第三方依赖、零网络。核心逻辑全部 Python 标准库实现，git clone && python eval.py 即可复跑 137 条断言，不依赖任何外部服务或 API Key，评审与二次开发者都能一次跑通。
