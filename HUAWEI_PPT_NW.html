一、场景背景

企业开始把交易审批交给 AI。但直接问一个大模型「这笔交易该不该做」，它会自信地回答，并引用它自己编造出来的数字——那不是风险工具，那是负债。

二、真实痛点（三条）

  • 幻觉被当作证据：模型输出的数值缺乏与事实字段的绑定校验。
  • 单智能体无对抗：一个模型自我审查，无法暴露自身盲点。
  • 多智能体投票反而放大幻觉：若不对每条论断做证据校验，投票等于把幻觉加权平均。
目标用户：需要 AI 辅助交易/采购/合规审批，但无法承受幻觉成本的企业与超级个体。

三、QuorumPilot 的应对：权力分离

  • 智能体只能提议：4 位专家提出论断，每条必须引用事实字段。
  • 验证器决定什么算证据：确定性代码逐条核对，不可证明者在投票前丢弃。
  • 仲裁器决定怎么做：纯算术、不使用模型，汇总幸存论断出裁决。

关键性质：仲裁器不调用任何模型。裁决结果不受任何大模型措辞影响——这是架构级保证，而非提示词约束。

验证器的硬规则

  • 每条论断必须引用事实快照中的某个字段；
  • 引用不到 / 与字段不符 → 判定不可证明；
  • 不可证明的论断在进入投票前被丢弃，不参与汇总。
因此系统不会把「模型自信但未被引证」的说法计入决策，从结构上消除幻觉进入裁决的路径。

核心亮点：不可证明即丢弃

差异化创新点 · 对应评分维度「专业贴合与创新 25 分」

亮点 1 · 证据优先于意见

多数多智能体方案让智能体投票后直接采纳多数意见。QuorumPilot 在投票之前插入确定性验证：智能体的每条论断必须先绑定事实字段，绑定不上就被丢弃。这意味着模型无法靠"说得更自信"影响结果——它只能靠提出可被引证的论断来影响结果。

亮点 2 · 仲裁器不用模型

最终裁决由纯算术汇总产生，杜绝了"让 LLM 再判断一次"带来的二次幻觉与措辞敏感性。裁决可被独立重算与审计。

亮点 3 · 对抗式多智能体

4 位专家从不同视角审查同一笔交易，天然形成对抗，暴露单智能体盲点；而对抗的结果仍受验证器约束，不会退化为"多数人的幻觉"。

亮点 4 · 零依赖 + 完全离线可复现

  • 纯 Python 标准库，pip install 无内容。
  • 引擎双通道：OpenAI 兼容 LLM 或确定性离线引擎（brain.py），模型不可用时自动降级，评测不依赖任何 Key。
  • 137 条断言覆盖完整流水线，离线一次跑通。

亮点 5 · 工程交付完备

  • Web 界面（web.py）+ HTTP 服务（app.py）
  • MCP 服务器（mcp_server.py）——可作为工具被其他智能体调用
